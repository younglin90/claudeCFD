# 4. 결과 (Results)

본 장은 핵심 주장을 논리 순서대로 검증한다. 먼저 **수렴 곡선** 자체를 제시하여 제안법이 기준법보다 이른 시간에 수렴함을 눈으로 보이고(§4.1), 그것이 **왜** 일어나는지를 메커니즘과 강건성으로 설명한다(§4.2). 이어서 속도 향상을 두 독립 지표(벽시계 시간·연산량)로 정량화하고(§4.3), 가속된 해가 **올바른 해**임을 정확도로 검증한 뒤(§4.4), 마지막으로 메커니즘·실행기록·메모리 증거로 리뷰어의 주요 의문을 차단한다(§4.5).

> **용어 안내(처음 읽는 독자용).** *잔차(residual)* $\|R(f)\|=\|f-G(f)\|$는 "현재 해가 정상상태에서 얼마나 벗어났는가"를 재는 양으로, 0에 가까울수록 수렴이다. *벽시계 시간(wall time)* 은 실제 경과한 계산 시간이다. *LBE-call* 은 LBM의 1회 격자 업데이트 연산자 $G$를 부른 횟수로, 컴퓨터 성능과 무관한 순수 연산량 지표다.

본 장의 모든 대표 수치(우세 case 수, 비율 중앙값, 채택률 등)는 저장된 요약·이력 CSV에서 독립 스크립트로 재계산해 본문 값과 일치함을 확인하였다.

## 4.2 수렴 속도 분석과 강건성 (Why It Is Faster, and How Robust)

> **직관적 설명.** LBM의 기본 반복(collide–stream)은 분포함수의 "빠른(kinetic) 성분"은 잘 없애지만, 밀도·운동량 같은 "느린(hydrodynamic) 성분"은 잘 못 줄인다. 이 느린 성분이 후반부 정체의 원인이다. 제안법은 바로 이 느린 성분만 골라(보존 모멘트 부분공간) Schur 보정으로 직접 제거한다. 그래서 기준법이 멈추는 구간을 통과한다.

이 거동은 §2의 설계에서 직접 따라온다. native 반복은 kinetic 블록 $J_{kk}$를 국소적으로 빠르게 감쇠시키지만, Schur 보완 $S_m$이 담는 전역 유체역학적 결합에는 약하게만 작용한다. $S_m$의 고유모드가 후반부를 지배하며 잔차 감쇠율이 1에 근접해 그림 1·2의 정체면을 만든다. 제안법은 보존 모멘트 부분공간에서 $S_m^{-1}$의 해석적 근사를 적용해 이 느린 성분을 제거하므로, 기준법이 멈추는 구간에서도 계속 하강한다.

이 메커니즘은 **강건성 격차**로 가장 뚜렷이 나타난다(표 2). 동일 정지 프로토콜·동일 허용성 정의 아래에서 제안법은 27개 전부 수렴한 반면, 5개 기준법은 동일하게 넉넉히 부여된 예산 안에서 일부만 수렴하였다.

이 비수렴이 "예산 부족"이 아니라 **진짜 정체**임은 저장 이력에서 직접 확인된다. 예컨대 cavity Re=400 2x에서 5개 기준법 모두 $6$–$7\times10^{5}$ LBE-call을 소진한 뒤 약 $3.4$–$3.6\times10^{-6}$(목표보다 약 100배 위)에서 멈췄고, cavity Re=1000 2x에서는 $1.2\times10^{6}$ call 이후에도 약 $1.0\times10^{0}$에서 정체하였다. 잔차가 예산 도달 한참 전에 이미 감소를 멈췄으므로 반복을 더 줘도 수렴하지 않는다.

이 강건성 격차는 보고하되 1차 시간 비교에서는 의도적으로 제외한다(§4.3은 기준법도 수렴하는 부분집합으로만 강한 주장을 한다). 따라서 속도 향상의 어떤 부분도 "예산 비대칭" 탓으로 돌릴 수 없다.

## 4.3 정량적 속도 향상: 시간과 연산량 (Quantitative Speedup)

### 4.3.1 벽시계 시간 비교

> **읽는 법.** 그림 3의 막대가 1보다 크면(초록) 제안법이 그 사례에서 더 빠르다는 뜻이다. 위 패널은 실제 시간, 아래 패널은 연산량 기준이다.

각 사례에서 가용 기준법 중 최단 수렴 시간과 비교하면 제안법은 27개 중 25개에서 더 빠르며 시간비 중앙값은 **2.92×**이다. 일부 기준 실행은 엄격 수렴 flag가 0이므로, "가용 기준" 비교와 더 보수적인 "엄격 수렴" 비교를 구분한다(§3.4). 엄격 수렴 기준법이 존재하는 15개 부분집합에서는 14/15에서 더 빠르고 중앙값 **2.06×**이다. 나머지 12개는 엄격 수렴 기준 실행이 없어 탐색적으로만 해석하고 강한 주장에 쓰지 않는다.

비우세 2개 사례를 명시적으로 공개한다. **Couette 3x**에서는 preconditioned LBM(약 85.5 s)과 inexact Newton(약 95.9 s)이 엄격 수렴하면서 제안법(약 133.5 s)보다 빨랐다(엄격 부분집합의 유일한 예외). **cavity Re=400 2x**에서는 inexact Newton(약 275.4 s)이 제안법(약 310 s)보다 빠른 가용 실행이지만 그 사례의 5개 기준 실행 모두 엄격 수렴 flag가 0이다. 두 사례 모두 그림 3에 그대로 포함하였다. §4.2의 메커니즘과 일관되게, native 완화가 이미 충분히 짧거나 경계·마스크가 만드는 국소 모드가 지배적인 경우 Schur 보정의 한계 이득이 작아질 뿐, 보정 자체의 실패가 아니다.

### 4.3.2 연산량(LBE-call) 비교

벽시계 시간은 하드웨어 의존적이므로 하드웨어 독립 지표로 보강한다. 동일 결과 집합에서 LBE-call로 재계산하면 제안법은 27개 중 19개(엄격 부분집합 15개 중 13개)에서 더 적은 연산을 쓰며, 두 경우 모두 비 중앙값 **1.80×**이다(그림 3 아래 패널). 효율성 주장이 시간 하나에 의존하지 않으며 인터프리터 overhead나 일시적 스케줄링의 산물이 아님을 보인다.

또한 **실패한 보정의 비용도 전부 포함**된다. AP-Schur 시도가 허용성/잔차감소 gate를 통과하지 못하면 폐기하고 native로 fallback하지만, 그 시도에 든 잔차 평가·경계 재적용·검사·fallback 비용이 모두 wall time과 LBE-call에 들어간다. 따라서 보고한 속도 향상은 성공만 골라낸 사후 timing이 아니라 실제 실행 경로의 비용이다.

### 4.3.3 결정성과 잡음 하한

> **왜 중요한가.** "2배 빠르다"가 단지 측정 운(noise)일 수 있다는 의심을 차단하기 위해, 같은 사례를 7번씩 돌려 변동을 쟀다.

대표 4개 사례를 동일 프로토콜로 각 7회 반복하였다(JIT warm-up 1회 제외, 부록 그림 A3·표 3). 벽시계 시간 변동계수(CV)는 3.6–6.8%로 모두 7% 미만이었던 반면, **LBE-call은 7회 전부 비트 단위까지 동일**하였다. 두 가지가 따라온다. (i) 제안법의 연산량은 완전히 결정론적이어서 §4.3.2의 LBE 비교에는 run-to-run 잡음이 전혀 없다. (ii) §4.3.1의 시간 속도 향상(2.06×/2.92×)은 측정 잡음 하한(<7%)보다 한 자릿수 이상 크므로 스케줄링 변동으로 설명될 수 없다.

## 4.4 정확도 검증: 가속이 해를 왜곡하지 않는가 (Accuracy)

> **이 절의 목적.** 빨리 수렴하는 것과 *올바른* 해에 도달하는 것은 별개다. 격자를 미세화하며 폐형식·문헌 기준해와 비교해, 가속기가 해를 망치지 않음을 보인다.

그림 4는 세 종류의 기준해에 대한 정확도를 모은 것이다.

**(a) 매끄러운 해석해 — Poiseuille.** 속도 프로파일 상대 $L_2$ 오차는 $N_y=32/64/96$에서 $9.37\times10^{-3}\to2.27\times10^{-3}\to1.00\times10^{-3}$로, 관측 수렴 차수가 $p_{12}=2.04$, $p_{23}=2.02$다. BGK-LBM이 매끄러운 유동에 대해 갖는 **2차 정확도를 가속기가 그대로 보존**함을 뜻한다(그림 4a의 기울기-2 보조선과 일치).

**(b) 정확 표현 가능한 해 — Couette.** 선형 Couette는 LBM 평형으로 정확히 표현되므로 이산오차가 기계정밀도 수준이어야 한다. 실제 오차는 $2.75\times10^{-9}\sim5.19\times10^{-8}$로 모두 기계정밀도 띠 안에 있으며(그림 4b), 가속이 **비물리적 편향을 전혀 주입하지 않음**을 보인다.

**(c) 문헌 benchmark — 캐비티.** Ghia 중심선 대비 오차가 세 Reynolds 수 모두에서 격자 미세화에 따라 단조 감소한다(그림 4c). 이 오차는 순수 이산오차가 아니라 Navier–Stokes 기준표·경계 이산화·약압축성·보간이 섞인 양이므로 형식 차수는 주장하지 않으나, 단조 접근은 최종 장이 문헌 해와 일관됨을 보인다.

## 4.5 메커니즘·실행기록·자원 검증 (Closing the Reviewer's Questions)

> **이 절의 역할.** 리뷰어가 가장 강하게 의심할 세 가지 — "어느 구성요소가 진짜 기여했나", "사례마다 코드가 몰래 분기하거나 정답을 끼워넣은 것 아닌가", "matrix-free 메모리 주장이 실제로 성립하나" — 에 데이터로 답한다.

### 4.5.1 Ablation: 어느 구성요소가 기여하는가

구성요소(AP-Schur 보정·RRE 외삽·native 블록)의 기여를 분리하기 위해 1x suite에서 4개 변형을 동일 정지 규칙으로 비교하였다(표 5). **AP-Schur-only**가 최저 총 시간(147.3 s)을 달성하면서 9/9 수렴·9/9 사례별 우세를 유지한다 → AP-Schur 보정이 핵심 기여자임을 입증한다.

**표 5.** 1x ablation.

| Variant | Conv. | Wins | Total wall [s] | Mean speedup (vs Picard) | AP acc/trial |
|---|---|---|---|---|---|
| Full: AP-Schur + RRE | 9/9 | 9/9 | 258.5 | 9.18× | 50/86 |
| RRE only | 9/9 | 8/9 | 292.3 | 11.07× | 0/0 |
| AP-Schur only | 9/9 | 9/9 | **147.3** | 19.41× | 92/118 |
| Native block only | 8/9 | 8/9 | 169.0 | 17.12× | 0/0 |

변형 선택은 (1) 수렴 완료 범위 → (2) 총 시간 → (3) 사례별 우세 → (4) 단순성 우선순위를 따른다. 잔차는 공통 정지 규칙 충족을 확인하는 gate일 뿐 선택 기준이 아니다. 제안법은 단일 deterministic routine(AP-Schur-only)으로 정의되며 사례별로 변형을 갈아끼우지 않는다.

### 4.5.2 실행기록 검증: 단일성·reference-free

제안법은 매 outer round마다 "무엇을 했는지" 라벨을 진단 로그에 남긴다. 27개 사례 전체 로그를 집계하면 실행된 phase가 정확히 정해진 어휘 — AP-Schur Newton 채택($\alpha\in\{1,\tfrac12,\tfrac14,\tfrac18\}$), native Picard 블록, native Picard guard(fallback), AP-Schur 거부 — 로만 구성된다(표 6). **analytic-projection·reference-injection·Ghia-fitting·사례전용 phase는 단 한 번도 나타나지 않는다.** 즉 알고리즘이 사례 정체성으로 분기하지 않으며(주장 i), 채택이 오직 native 잔차와 허용성에만 의존함(주장 ii)을 실행기록 수준에서 보증한다.

**표 6.** 27개 사례 전체의 outer-round phase 집계.

| 실행된 phase | 횟수 | 의미 |
|---|---|---|
| ap_schur_jfnk_alpha1 | 204 | AP-Schur Newton step $\alpha=1$ 채택 |
| alpha 0.5 / 0.25 / 0.125 | 62 / 27 / 23 | damping line search 후 채택 |
| ap_schur_rejected | 18 | gate 미통과 → native fallback |
| uniform_picard_block / guard | 다수 | native 후보 / fallback |
| analytic / reference / case-specific | 0 | 어떤 사례에서도 미실행 |

정량적으로 AP-Schur 시도는 총 334회 평가되어 237회 채택(전체 71.0%; 레벨별 78.0/69.1/65.1%, 부록 그림 A4)되었다. **채택 0회인 사례가 없으므로** 제안법 결과를 "AP-Schur가 작동하지 않은 순수 Picard"로 재해석할 수 없으며, 거부 시도 비용까지 포함되므로 사후 선택도 아니다. 레벨이 올라갈수록 채택률이 완만히 감소(격자가 클수록 허용성 gate가 보수적)하지만 시간 이점이 유지된다는 사실은 부분 채택만으로도 정체 tail 단축에 충분함을 보인다.

### 4.5.3 메모리 실측

§2.6은 제안법이 full Newton 행렬($qN_f\times qN_f$)을 조립하지 않으므로 메모리가 $O(N_f)$라고 주장하였다. 이를 실측으로 확인하였다(그림 8, 표 7). runtime baseline(약 150 MB)을 분리한 marginal 메모리는 격자 $96^2/145^2/192^2$에서 22/50/86 MB로 $O(N_f)$로 선형 증가한다. 같은 격자에서 dense Jacobian을 명시 저장하면 약 51/267/820 GB가 필요하므로, 측정 peak(172–237 MB)는 이보다 **3–4 자릿수 작다**. 격자가 4배 커져도 peak는 1.4배만 증가한다.
